# StreamHub Support

A customer-support demonstration for a fictional streaming service, created for MSAI 631.

## How it works

Every reply is generated by a language model (default `Qwen/Qwen2.5-0.5B-Instruct`, via
Hugging Face `transformers`), not from hardcoded strings. The bot's scope is kept narrow
and consistent by grounding every call in a fixed system prompt (`INSTRUCTIONS` +
`SUPPORT_FACTS` in `support.py`) rather than by retrieval or fine-tuning, which is the
prompt-only design described in the project proposal. Each turn sends the policy plus the
last few conversation turns, so the model can track troubleshooting progress without
inventing new facts.

The proposal's initial candidate was `google/flan-t5-base`. In testing it tended to echo
conversation text instead of replying, so the team switched to Qwen2.5-0.5B-Instruct, a
similarly small open instruction model that runs on a laptop CPU, as the proposal allowed.

Replies stream into the chat word by word as they are generated. Two caches make it faster:

- **Response cache.** Decoding is deterministic, so an identical question in an identical
  conversation always gets the same answer. Those answers are saved in
  `.cache/streamhub_responses.json` and returned instantly, including after a restart.
  Matching ignores case and trailing punctuation. Entries automatically stop matching if the
  model, the policy text, or the generation settings change. Delete the file to clear it, or
  set `STREAMHUB_CACHE_FILE` to an empty value to keep the cache in memory only.
- **Prompt prefix cache.** Every conversation starts with the same system prompt, so the
  model processes it once at startup and each request reuses that work, only reading the
  conversation turns that follow.

The terminal logs how long each reply takes (time to first words and total), which is
useful for the results paper.

The interface uses a Teams-inspired support layout: a clear top bar, topic shortcuts, familiar chat bubbles, and a focused message composer. It does not claim to be Microsoft Teams or use Microsoft branding.

## Supported questions

- Playback troubleshooting: restart, check the connection, then reinstall.
- Seven-day free trial.
- Monthly billing cycle.
- Plan changes apply at the next billing cycle, without mid-cycle proration.
- Refund limitations.
- Simultaneous streams: explained as plan-dependent; exact limits are intentionally not included.

The app cannot access accounts, process payments, change plans, or accept sensitive information.

## Run locally

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py
```

Open the URL Gradio prints, normally `http://127.0.0.1:7860`.

The first run downloads the model (about 1GB for Qwen2.5-0.5B-Instruct) from Hugging Face,
so it needs internet access once; after that it is cached locally. The model loads at
startup, so if anything goes wrong (no network, missing package) the full error prints in
the terminal before the app opens.

### Choosing a model

Set the `STREAMHUB_MODEL` environment variable to swap models without code changes:

- **Chat-tuned instruction models** (default `Qwen/Qwen2.5-0.5B-Instruct`): get the policy
  as a system message and the conversation through the model's chat template.
- **Encoder-decoder instruction models** such as `google/flan-t5-base`: get one flattened
  prompt. Kept for comparison with the proposal's original candidate.

```powershell
$env:STREAMHUB_MODEL = "google/flan-t5-base"
python app.py
```

## Validate

```powershell
python -m unittest discover -v
```

The unit tests replace the model with a stand-in, so they need no download and run in a few
seconds. They check prompt construction, word-by-word streaming, the response cache (hits,
misses, persistence, invalidation when the model changes), fallback behavior, and Gradio
chat formatting. They do not check the *content* of real model output; do a manual pass in
the running app (see `VALIDATION.md`) to confirm the model's answers stay grounded in the
policy for each of the six supported scenarios.
